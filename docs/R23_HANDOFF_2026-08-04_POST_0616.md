## Final r37 correction made immediately before the production run

The r37 edit was narrow and is the newest code change in this handoff:

1. `Module13_ProjectionResolution.MapVisibleDatumEntity` first attempts
   `IView.GetPolylines7` visibility mapping.
2. Only when that API explicitly returns **no edges** (`status=NoEdges`) may it
   fall back to `IView.SelectEntity` plus
   `ISelectionMgr.GetSelectedObjectsDrawingView2` ownership proof.
3. It does **not** fall back when a non-empty polyline array exists but no
   identity match is found. That remains fail-closed, because accepting an
   arbitrary drawing edge would corrupt the datum.
4. `Module15_OrdinateScheme` records mapping-route evidence and uses the new
   visible-datum route for the vertical bottom-outline datum.
5. `Module1_Main.bas`, relevant contracts, `README_IMPORT.md`,
`CURRENT_STATUS.md`, `R23_IMPLEMENTATION_PLAN.md`, `Changelog.md`, and
   `SOLIDWORKS_API_VALIDATION.md` were updated to revision r37.

The selection fallback passed on the P-0251 scratch drawing. The later fresh
production drawing returned non-empty polylines, so it correctly did **not**
take that fallback and the datum remained unresolved. This is the active
production defect, not a reason to weaken the guard.
