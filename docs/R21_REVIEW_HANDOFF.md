# R21 review handoff

R21 contains **no new features**. It is r20 with fixes for defects found in a
full review of the r20 diff. This document exists so a second reviewer can
check the fixes without re-deriving the findings.

**R21 has never been compiled or run.** Everything below was verified by
reading code and checking API contracts. Full-project **Compile Project** in
the VBA editor and a focused P-0251 run are still required.

## The seven correctness findings

### 1. Cylinder fallback used the wrong point as the hole centre

`Module5_FallbackDimensionEngine.bas`, `TryReadClosedCircularEdge`

R20 added a fallback: when a closed edge's underlying `ICurve.IsCircle` is
false, read the geometry from `ISurface.CylinderParams` instead. The array that
returns is `origin.x/y/z, axis.x/y/z, radius` — and **origin is an arbitrary
point on the cylinder axis**, not the centre of the edge being measured.
`BuildOwnedCandidate` then used elements 0–2 as the hole centre.

Two consequences: an oblique bore was dimensioned at a point that is not on its
opening, and both circular edges of one cylinder produced the *same* centre, so
the top and bottom of a bore became indistinguishable.

The fix projects the origin along the axis into the plane of the edge, using a
point known to lie on the edge (`curveParameters.StartPoint`):
`centre = origin + ((p − origin) · â) · â`.

**Worth checking:** that this is the right correction rather than rejecting the
edge outright. The fallback exists because r19 produced zero candidates, so
deleting it would regress that — but if the fallback is only ever expected to
fire for genuinely circular openings, rejecting non-circular ones may be the
more honest behaviour. That is a design call, not a correctness one.

### 2. Outline containment blocked the Center datum

`Module8_RuntimeSupport.bas` `TransformPointToView`; `Module5` `ProveCenterDatum`

R20 made every transformed point prove it lies inside `IView.GetOutline`. That
is correct for a hole centre — it must be on visible geometry. It is wrong for
the **projected model origin**, which `ProveCenterDatum` transforms as a
reference point. A part whose origin sits off the solid (a plate corner, a
mounting face, anywhere outside the silhouette) failed the transform and the
function returned before examining a single vertex, making the Center datum
permanently unprovable.

Containment is now a required argument on `TransformPointToView`: `True` for
hole centres and mapped model vertices, `False` for the projected origin. When
containment is not required the point still gets a proof token, tagged
`containment=NotRequired`, so the evidence still records what was measured.

**Worth checking:** the three call sites got the right flag.

### 3. Ordinate chains were given one baseline per dimension

`Module4_ModelItemImporter.bas`, lane fallback

The deterministic lane fallback (used when `AlignDimensions` returns False)
incremented a lane counter for every dimension, so eight horizontal ordinates
landed on eight baselines 6 mm apart. An ordinate chain is defined by sharing
one baseline, so the fallback was destroying exactly what it was arranging.

Separately, `swDimensionType_e` defines `swOrdinateDimension = 1` as "base
ordinate and its subordinates". Type 1 was not in the type switch, so real
chains fell into `Case Else` and were routed by nearest-side proximity — which
can split one chain across the top and bottom of a view. `Module6` already
counted type 1 as an ordinate, so the two modules disagreed.

Now: ordinates on a given side share one lane; non-ordinates still get their
own; types 1 and 16 are recognised. Lane state moved to module-level variables
reset per view, which also removed four threaded `ByRef` counters.

**Worth checking:** `ResetDimensionLaneState` is called at the top of every
view transaction. Module-level state is only safe because the fallback is
single-threaded and per-view.

### 4. Only MirrorPattern got seed resolution

`Module3_ModelAudit.bas` `IsOwnedHoleFeature`; `Module5` `BuildOwnedCandidate`

`IFace2::GetSeedFeature` resolves "patterned, mirrored, or copied" bodies, but
r20 wired it to the single feature type `MirrorPattern`. A linear or circular
hole pattern returned False from `IsOwnedHoleFeature`, so the feature never
entered `GetAllHoleLikeFeatures` — producing **no candidate and no rejection
record**, which is the hardest kind of failure to notice.

A shared `IsPatternFeatureType` now covers the pattern families.

**Worth checking:** the type-name list. These are `GetTypeName2` strings and I
assembled them from the documented family rather than from a live model. If a
name is wrong the behaviour is unchanged from r20 for that family (silently
dropped), not broken — but it is worth confirming against a real part.

### 5. FACE and SIDE callouts shared a position

`Module7_TitleBlockEngine.bas` `GetManufacturingCalloutTarget`

Both computed `targetX = outline(0)`, `targetY = outline(1) − 0.008`. Nothing
in `FindManufacturingCandidate` forces those two candidates into different
views, so when they share a view the second note is placed exactly on the
first, `CalloutExtentClearsOtherAnnotations` detects the overlap, and
`MANUFACTURING_DEFINITION` fails — which `Module6` turns into a hard P-0251
acceptance failure. SIDE now sits at `−0.026`.

**Worth checking:** whether 18 mm of separation is enough for two-line notes at
the drawing's text height, and whether the SIDE lane can be pushed below the
content border on a tall view. `ManufacturingDefinitionExtentIsSafe` will catch
that and fail, so it is safe but possibly still failing.

### 6. The callout could collide with itself

`Module7_TitleBlockEngine.bas` `CalloutExtentClearsOtherAnnotations`

The scan skipped the callout being placed using `Is` against
`currentAnnotation`. But the loop re-fetches `otherNote.GetAnnotation`, and
`Is` compares IUnknown pointers — if SOLIDWORKS returns a fresh dispatch
wrapper for the same annotation, the callout is compared against its own extent
and "collides" every time.

Identity now also matches on annotation name, with the pointer check kept as a
fast path. Name matching only applies when a name is actually available, since
treating two unnamed annotations as identical would skip real collisions.

**Worth checking:** this is the finding I was least certain about. It may be
that SOLIDWORKS does return a stable pointer and r20 was fine. The fix is
harmless either way, but if you can confirm the pointer behaviour, the name
fallback could be dropped.

### 7. General notes could never be proved

`Module7_TitleBlockEngine.bas` `NoteReferencesSemanticField`

The controlled format carries its general notes as **static text** — the
recorded probe shows the note's linked value is the literal string, no `$PRP`.
Nothing the macro writes can change it. But `PopulateTitleBlock` sources the
expected text from a part custom property (`GeneralNotes` / `General Notes` /
`DrawingNotes`), falling back to the hard-coded constant only when that is
empty. Any part carrying such a property produced an expected value that no
note on the sheet could ever match, failing the stage on a correct drawing.

The controlled reference constant is now accepted as well, and
`NoteReferencesSemanticField` returns which text actually proved the note so
the later containment check tests the same string.

**Worth checking:** whether accepting the constant is right, or whether the
property should simply not be consulted for a format whose note is static.

## The six robustness changes

These do not fix wrong output; they stop correct drawings being rejected, or
make failures diagnosable.

1. **`Module6`** — dropped the exact-equality check between the section-line
   array length and `GetSectionLineCount2`'s `Size`. The docs never define
   `Size` as the raw array length, so an off-by-one convention difference would
   reject every drawing. The cursor guards already bound every read. **The
   parsing itself was checked against the documented layout and is correct as
   r20 wrote it — strides of 7 (lineType + start[3] + end[3]), 9, 9, 7. No
   change was made there.**
2. **`Module6`** — malformed section arrays now report what failed and where.
3. **`Module4`** — selection readback no longer must equal the `Select3`
   success count; only an empty selection fails.
4. **`Module8`** — widened the legacy title-block bottom-edge window from an
   8.9 mm band to one that admits a 20 mm border. Replaying the recorded
   P-0251 template sketch gives identical bounds before and after.
5. **`Module8`** — removed two contract checks that compared the measured
   rectangle against limits its own candidate filter had already enforced.
6. **`Module8`** — deleted `ViewToSheetCoordinates` (identity copy, no
   callers). **`Module5`** — per-vertex transform proofs log only on rejection.

## What a reviewer should attack first

1. Finding 1 — is projecting onto the edge plane correct, or should a
   non-circular closed edge be rejected?
2. Finding 4 — are the pattern type-name strings right?
3. Finding 3 — does sharing one ordinate lane actually produce a usable
   drawing, or does it need the ordinates ordered along the lane too?
4. Finding 6 — does SOLIDWORKS return a stable annotation pointer?
5. Anything in r20 (`f2b2b29`) I did not flag. The review covered the whole
   diff, but a second pass on `Module4`'s arrange staging and `Module7`'s
   callout creation would be worthwhile — those are the largest new surfaces.
